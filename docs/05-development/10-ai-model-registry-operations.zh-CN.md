# AI 模型注册表操作与参数兼容性优化

## 设计依据（2026-09-06）

- [LiteLLM 参数兼容](https://docs.litellm.ai/docs/completion/drop_params)：不支持的参数默认报错，允许按模型控制参数丢弃或透传。项目不启用全局静默丢弃，以免工具、结构化输出等业务要求被移除。
- [LiteLLM 健康检查](https://docs.litellm.ai/docs/proxy/health)：进程存活/就绪与模型实际请求健康是不同维度。
- [Ant Design Table](https://ant.design/components/table/)：宽表格采用固定身份列、固定操作列、行选择及批量操作，长标识需要显式处理换行。

## 本轮落地

1. 管理状态与基础探测分开命名。绿色健康标签改为“基础探测通过”，结构化、工具和视觉诊断保留独立展示。模型启用不等于所有场景可用，TTL 到期仍显示过期状态。
2. 左侧固定模型身份，右侧固定检测、编辑、启停操作；模型别名允许长文本断行，避免横向滚动后丢失身份。
3. 单行快捷启停及跨页选择的批量启停，共用现有 `update_ai_model_registry_v1`，仅提交 status，不回写旧成本或治理元数据。提交原因由现有审计契约要求；后端继续执行管理权限、行锁和请求幂等。启用仍需要已有数据区域和留存信息。
4. 批量请求串行执行，处理中禁止重复提交和关闭对话框；成功项不重试，失败项保留别名及具体错误。批量不逐项弹通知，汇总成功与失败。
5. 停用提示影响已发布策略：后续资格检查排除停用模型，若无合格 fallback 则场景不可用。现有策略缓存有刷新延迟，本轮不承诺立即中断在途请求，也不修改线上策略。
6. Chat、意图和四类草稿共享请求构建器。环境默认 `reasoning_effort=none` 解释为“不额外发送推理参数”，避免对不接受该参数的模型造成确定性 HTTP 400；非空且非 none 的显式等级继续发送。不通过模型名称猜能力，也不自动删除明确等级。
7. 失败流没有 completed result 时，运行详情使用消息已经保存的固定/自动选择状态，避免固定模型被显示为自动选择。

## 已知边界与后续设计

基础能力探测和带完整业务参数的场景验收仍不同。本轮修复默认推理参数差异；后续应增加版本化参数能力配置和与已发布策略相同参数的场景探测，记录参数指纹、检测时间和失败层次。显式推理等级应按模型验证，不能仅靠基础健康绿灯放行。

Provider HTTP 400 仍使用现有 `MODEL_PROVIDER_REJECTED` 错误族；细分不兼容参数、认证、配额以及持久化 provider code 需要单独扩展错误契约。意图降级工具事件的“完成”语义仍需完善，不能把本轮登记为该问题已经修复。

启停本轮提供影响说明，未增加逐策略变更预览、批量原子事务或强制抢占在途请求。没有执行真实模型启停、线上部署或正式业务写入。

## 验证

- Orchestrator：Ruff、pytest、Docker test/runtime。
- Web：TypeScript、Biome、Jest；定向验证失败流固定选择和快捷停用只传 status。
- 本轮不变更 Backend API 签名；沿用已有权限、审计和幂等接口。
