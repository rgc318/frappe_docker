# AI 动作一致性与能力治理优化方案

## 目标

系统既要验证数据是否合法，也要验证动作是否忠实于用户要求。不支持、低置信度、多个目标未解析完整时，不得把请求替换为创建、编辑、停用或其他相近操作。业务确认不能替代语义校验。

本方案覆盖 Web → Gateway → adapter → Service → Orchestrator，以及会话状态、草稿执行和模型能力治理。保留现有版本控制、权限、幂等、领域服务与正式回执，不修改 Frappe/ERPNext 源码，不授权自动删除商品或单据。

## 统一契约

后续新增版本化 `ai-action-contract-v1`，与现有场景分类并行，不直接破坏旧 Schema：

| 字段 | 用途 |
| --- | --- |
| request_mode | execute_request / inquire / negate / clarify，区分命令、咨询、否定和待澄清 |
| actions[] | 原始动作、对象类型、明确目标、保留目标、修改字段、依赖关系 |
| support_status | supported / unsupported / clarification_required / partially_supported |
| constraints | 公司、范围、数量、保留条件与禁止操作 |
| query_field_operations | 各查询字段的 keep / set / clear，不能以 null 或 all 猜测省略 |
| evidence | 原文证据片段与来源；不得把模型推断伪装为用户明确值 |
| resolution_id / hash | 服务端绑定用户、公司、会话版本、原文和附件，短期有效且可审计 |

服务端能力目录声明操作、对象类型、目标基数、所需权限、确认等级、是否支持部分执行及正式业务执行器。模型负责理解，不负责宣称自己能执行什么。未知动作失败关闭；删除不等于停用，取消单据不等于删除订单行，合并商品不等于编辑名称。

## 执行流程

1. 解析原始动作与明确否定；低置信度的写操作进入澄清，不允许关键词降级创建写草稿。
2. 通过服务端能力目录评估支持情况；不支持则返回能力说明和已有业务入口，不创建空编辑草稿。
3. 在权限范围内解析全部目标；“删除 2 个、保留 1 个”保留完整目标集合。目标缺失、重复或冲突时不执行。
4. 草稿生成接收 resolution_id，并绑定动作、范围与原文摘要。比较生成结果与原动作，不一致返回 ACTION_CONTRACT_MISMATCH。
5. 页面展示原始要求、将执行的动作、对象清单、保留对象、未支持部分及原因。混合请求默认整体澄清，不静默只做支持的部分。
6. 执行前重读权限与数据版本，验证契约、目标集合和草稿版本后再次明确确认；仍由现有领域服务执行并保存回执。

查询 keep/set/clear 必须贯穿 Prompt、JSON Schema、Backend 合并与测试。显式 clear 永不从历史恢复；缺少新契约的旧响应不允许凭关键词恢复一个可能被明确清除的条件。迁移必须分别测试续接查询和重置查询，不能用修复清除的方式破坏正常续接。

## 模型能力治理

基础健康与工具/结构化/视觉资格独立。瞬时超时、429、5xx 不等于能力不存在；各能力应有状态、最近成功、最近失败、错误类型、有效期与模型配置指纹。过期和未检测不能等同 unsupported。第一阶段先统一瞬态失败保留规则，后续迁移至逐能力状态机；基础探测不能无限刷新能力证据有效期。

异步模型检测继续使用既有任务引擎，后续补 outbox 补投、worker 心跳、任务历史与保留期。旧同步接口调用方需要登记与迁移，迁移完成前不得宣称所有入口都受同一活动槽控制。

## 分阶段交付

- P0：先阻断已经证实的危险默认值。未知商品/订单动作拒绝；低置信度写意图禁止关键词晋升；统一能力瞬时失败保留。新增确定性测试并运行原回归。
- P1：实现动作契约、服务端能力目录、unsupported/clarify 反馈，接入自动入口和四类草稿直调入口；截图中的删除请求必须不再创建编辑草稿。查询字段 keep/set/clear 同阶段贯穿。
- P2：四类草稿绑定 resolution_id，执行前动作与完整目标集合校验；Web 展示支持范围、差异及保留对象，完善模型选择与执行状态反馈。
- P3：逐能力证据和配置指纹、检测任务运行恢复、审计指标与线上灰度。

阶段分别验证和记录，不把 P0 登记为全部完成。未实现删除执行器前，正确行为是明确不支持；不得为了展示“能做”绕过库存、单据引用和权限约束。

## 验收矩阵

必须覆盖商品、销售订单、采购订单、库存、查询与模型治理：

- 正常创建/修改；取消单据与移除订单行区分；删除商品与清空字段区分。
- 否定、咨询能力、低置信度、模型不可用、显式固定场景直调。
- 多目标、保留其中一项、部分支持、组合动作及依赖失败。
- 上下文续接、新实体、新图片、明确全部时间/不限金额/清除全部筛选。
- resolution_id 过期、跨用户/公司、原文变化、草稿版本变化、重复确认。
- 工具/视觉/结构化 429、超时、5xx、确定性不支持、未检测、证据过期。

测试分层：纯函数/服务单测、Gateway 不跳过 adapter 的契约测试、真实 HTTP、Web 交互、受控模型评测。模拟路由测试不冒充真实模型或浏览器验收。指标区分路由完成、语义一致、草稿可执行和正式执行成功，不能仅统计 Run completed。

## 回滚与发布

### P1 增量实现状态

已增加 erp-intent-v7 的 action_contract / query_context_operations，Backend 独立能力目录覆盖四类草稿，自动入口拒绝 unsupported、咨询/否定、多目标以及缺少契约的写入意图。明确查询重置/清除覆盖旧条件继承。该版本仍是初步契约：operations 和对象数量不是最终完整目标清单，不具备原文证据绑定；四类草稿直调与执行前契约绑定、专门澄清 UI、完整 keep/set/clear 和逐能力证据仍待实现。不要把这一步登记为全链路完成。

新增字段先以兼容版本进入；旧客户端读取保留，但未知写动作始终拒绝。分别提交 Backend、AI、Web；AI 推送后父仓固定指针。先本地确定性与 HTTP 验证，再按授权部署。存在动作不一致、权限隔离失败或错误业务写入时必须阻断发布。
