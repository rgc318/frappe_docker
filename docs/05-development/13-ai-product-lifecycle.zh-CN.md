# AI 商品生命周期操作

## 范围与状态

支持目标为 enable、disable、delete 三种独立动作，不扩展订单取消或商品合并。AI 负责理解原文及解析完整目标集合，Backend 负责权限、预检、版本、确认、事务与审计。删除不替换成停用，失败不静默部分执行。

已接入 Backend、AI 意图解析、公开 Gateway 和 Web 工作台。自然语言启用、停用、删除先生成独立持久计划；不会生成商品编辑草稿，也不会由模型直接执行。工作台顶部“商品操作计划”及聊天内计划卡片均可重新读取服务器计划。

计划 15 分钟有效、版本固定为 1、owner 隔离，不提供修改计划接口；启停要求两个显式布尔确认（全部目标、共享范围），删除另加专项确认，并要求非空幂等键。同 owner 请求号数据库唯一，成功重放返回原回执；过期后仍允许读取/重放已完成回执，不重新写 Item。删除预检阻断时保留计划及原因，不转换为停用。

执行服务拥有整个请求事务：计划行锁→稳定顺序 Item 行锁→全部权限/版本重检→Item.save→独立计划回执；成功由外层请求提交，任何执行异常 full rollback，连同 Frappe after_commit 队列一起清理。不能将本内部执行器混入有无关待提交写入的复合请求。不是逐项调用具有独立请求幂等缓存的 disable_product_v2，避免批次部分回执先缓存；正式启停仍沿用同一 Item.save、权限与 hooks 路径。

本地已直接执行幂等建表 patch；部署必须运行 migrate 登记，并同步部署 Backend/AI 的 `erp-intent-v8`。当前本地 HTTP 已验证创建/读取/列表/放弃计划、严格布尔确认拒绝，以及真实模型 `resolve → generate` 删除路由；实际删除由站点隔离事务测试覆盖，包括 Gateway→adapter→原生删除，测试夹具全部回滚。未做真实浏览器或多进程压力验收，不把组件测试或 HTTP 测试称为浏览器端到端。

AI `product_targets` 与 `preserve_product_targets` 分开携带 query 和当前原文 evidence，数量必须完整一致；咨询、否定、混合动作、缺失证据及低置信度失败关闭。仅唯一精确匹配（含已解析上下文编码的规范化匹配）自动绑定；即使模糊搜索只有一个结果也须人工选择。超过 20 个候选不截断执行，而要求明确编码。所有候选组必须选择，解析后生成新的不可变计划并将旧计划标记 superseded。任何目标重复或与保留对象冲突整体拒绝。

Web 每次打开计划重新读取持久状态；候选选择后重新预检、清空确认。按服务器剩余秒数禁用过期计划，执行期间锁定关闭/重复点击；响应不确定时可刷新或使用同一计划幂等键重试，不自动重试删除。最近 50 条个人计划支持历史恢复与回执查看。

## 执行契约

1. 解析动作与全部目标，绑定原文、用户、会话版本及明确保留对象。名称含糊时展示候选，不能仅截取第一项，也不根据数组位置猜商品编码。
2. 用正式商品权限读取每个目标，形成完整预览。商品 Item 是共享主档，必须突出说明影响全部使用该商品的公司；会话公司不构成商品删除范围隔离。
3. 持久计划保存 operation、目标编码集合、各 Item.modified、原文 hash、owner、原因、有效期及不可变版本。客户端不能修改计划动作或目标；任何变化重新预检并重新确认。
4. 人工确认精确计划 ID/版本与全部目标。删除需要单独确认共享范围和不可直接撤销风险，不得由模型代确认。
5. 执行端核验幂等键、owner、权限、到期时间、版本；按稳定顺序锁定全部 Item 并再次预检。目标中任一失败则整批拒绝；同一事务执行，异常全部回滚。禁止忽略权限、忽略引用、force 删除或 SQL 直接删除 Item。
6. 启停复用正式领域逻辑；删除调用 Frappe 正式删除接口，保留 hooks 和引用校验。预检不是执行授权，也不能消除并发新增引用风险；正式删除失败必须回滚。外部向量/媒体清理用提交后任务及可恢复记录，不在数据库提交前发送不可逆外部删除。
7. 保存独立于 Item 的逐项回执（编码、名称、原状态/版本、动作、操作者、请求号、时间）；再次提交成功请求返回同一回执，不重复执行。

## 删除保守边界

- 库存为零不代表无历史：任何 Stock Ledger Entry（含已取消）都阻断。
- 首版存在 Bin、Item Price、变体或其他静态/动态引用即阻断，避免 ERPNext Item.on_trash 隐式清理关联对象。零库存 Bin 也不自动移除。
- 有 File 附件或 image 封面引用同样阻断，避免原生删除触发无法随数据库事务回滚的文件清理。
- 执行用 Item 锁定读取的 modified 比较计划版本，不只依赖普通快照读取。原生 on_trash 前对库存历史、Bin、Item Price、变体和 File 依赖做锁定读取；MariaDB/InnoDB REPEATABLE READ 下空谓词保留间隙锁。正式静态/动态引用检查仍保留。该机制不是跨任意第三方 SQL 写入的全局外键保障，不能承诺不存在框架之外并发写入留下孤立引用；此类扩展需统一写入约束及专门并发验收。
- Frappe 引用检查读取全站引用，但响应仅返回通用阻断原因，不泄露其他公司单据名称。
- 不通过调用 on_trash 模拟预检，该 hook 本身会写库。删除框架的 Deleted Document 不等于可承诺完整恢复，尤其附件及外部索引需独立恢复策略。
- 启停需要 write 权限，删除需要 delete 权限；所有目标先通过 read 权限，缺失或越权整体失败，不返回部分目标详情。
- 初始单批上限 20；空集合、重复编码、未知动作、空理由拒绝。编码必须来自已确认目标，不在预检中进行模糊搜索。

## 交付顺序与验收

1. 领域只读预检、权限与保守引用门禁。
2. 持久计划/幂等执行/审计、Gateway 与 adapter 契约、隔离夹具事务回归。
3. AI Schema/Prompt/目标解析接入，原文动作及多目标完整性校验。
4. Web 逐项预览、共享范围提示、确认与失败恢复。普通商品页面本次不新增另一套删除实现；公开领域 API 可供后续统一管理入口复用。

验收覆盖正常启停、无引用商品删除、同名候选、重复/保留目标、任一越权、已有流水但零库存、价格/变体/动态引用、版本过期、并发引用、同幂等键重放和冲突、批次中途失败回滚。真实删除测试只允许明确自建的隔离夹具，禁止以用户现有商品做删除验收。
