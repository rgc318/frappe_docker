# 历史站点归档凭据治理

## 已确认及本轮措施（2026-09-13）

- 父仓历史跟踪的 `sites-backup.tar.gz` 包含 `data/localhost/site_config.json`，其中有非空数据库密码。不得将密码写入日志、文档或工单。
- 本轮仅在内存中将该密码与本地 Backend 容器的站点配置比较：检查 1 个站点，匹配 0 个。没有尝试用历史密码登录，也没有检查远程 staging/production；不能据此断言所有环境的旧密码均已失效。
- 归档停止 Git 跟踪，并加入明确的根目录 `sites-backup*.tar*` / `sites-backup*.zip` 忽略规则。磁盘原件仍保留，移除跟踪前后 SHA-256 一致。没有删除备份、重新打包或改写 Git 历史。
- CI 新增 `deploy/security/check_tracked_secrets.py`：拒绝当前检出快照中被跟踪的 Frappe 运行配置文件，以及 tar/tgz/tar.bz2/tar.xz/zip 内包含同名配置的归档；只读文件名/归档目录，不提取内容或打印密码。损坏或成员超限归档失败关闭。
- 门禁不扫描历史提交、其他仓库、嵌套压缩包、加密归档或任意格式的密钥；不是通用凭据扫描器，也不是泄露事件已关闭的证明。本地未推送时，远程默认分支仍保留原状态。

## 仍需明确范围后执行

1. 确认仓库历史可见范围，以及该旧凭据曾使用/复用的本地、staging、production 或其他数据库账号；不在未知目标上反复尝试登录。
2. 对仍有效或不能排除复用的凭据，制定短维护窗口、Secret Manager 版本、数据库账号更新、所有消费者重载、连接验证及回滚方案，经确认后轮换。只改 env 不会更新已有数据库卷内的密码。
3. 把保留归档转移到访问受控的备份存储，按保留策略加密、限制访问并验证恢复；本轮没有移动或删除它。
4. 明确协作仓库、镜像、CI 制品、fork/clone 与备份中的历史副本范围，再决定历史重写/缓存清除方案。移除 HEAD 跟踪无法撤回已经分发的 Git 对象，历史重写也不替代密码轮换。

## 本地无敏感输出验证

```bash
python3 -m unittest discover -s deploy/security -p 'test_*.py'
python3 deploy/security/check_tracked_secrets.py
```

归档移除跟踪前，门禁确定性失败并仅输出路径；移除后通过。测试使用合成内容，不读取或修改真实凭据。
