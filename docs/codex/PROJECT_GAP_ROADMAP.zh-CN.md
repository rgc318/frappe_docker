# 项目差距与交付路线图

更新时间：2026-07-15

本文档是当前项目“哪些已完成、哪些仍未满足企业级需求”的统一索引。具体接口和领域规则仍分别以各模块技术设计为准；历史交接记录只描述当时状态，不作为当前完成度判断依据。

## 1. 当前总体判断

| 维度 | 当前成熟度 | 说明 |
| --- | ---: | --- |
| 核心进销存业务 | 约 88% | 销售、采购、收发货、开票、收付款、退货基础链路已形成 |
| 企业级业务治理 | 约 75% | 用户、打印、幂等和审计较完整；信用、批次、盘点审批仍缺失 |
| Web 管理端 | 约 85% | 核心业务页面齐全，仍有逆向链路、模板清理和浏览器验收缺口 |
| 移动作业端 | 约 80% | 销售采购移动流程较丰富，仍需发布验收、扫码作业和安全能力收口 |
| AI Copilot | 本地功能约 98% | 只读工具、三类草稿、模型治理、数据任务、OTLP/Langfuse、固定评测、真实 Embedding、582 个商品向量索引、高并发门禁和恢复演练已贯通；剩余集中在生产级异步观测、HA/Secret/SSO/告警、真实 staging 和外部 v2 Provider |
| 生产上线准备 | 约 70% | 已有部署脚本和说明，仍需 staging、备份恢复、监控及真实设备演练 |

当前不应再视为缺失的模块：

- JWT 登录、刷新、2FA 挑战和全设备注销。
- 企业级用户、角色、数据权限和安全摘要。
- 七类核心单据的单张/批量打印、审计、ZIP 和合并 PDF。
- 销售、采购核心正向交易链路和常用回退动作。
- 商品、客户、供应商、仓库、UOM 的第一版主数据治理。
- AI Copilot 的会话审计、流式回答、反馈、受控商品检索、订单查询和经营报表解释。
- AI Copilot 的销售订单、采购订单和库存调整结构化草稿、不可变版本、安全恢复、放弃与现有编辑器交接。
- AI Copilot 的本地 Langfuse trace/score、失败开放契约、Prompt 版本治理和 21 例合成固定评测集。

## 2. P0：上线前必须收口

### 2.1 库存盘点生命周期

当前：盘点可以直接提交正式 `Stock Reconciliation`。

缺口：

- 盘点草稿、冻结范围和重复盘点保护。
- 复核、确认入账、驳回、作废和取消。
- 盘点差异阈值、超限审批和责任人。
- 盘点批次、明细错误、变更历史和审计导出。

验收标准：从创建盘点任务到确认入账、撤销和审计可完整追溯，任何一步失败都不会留下部分库存结果。

### 2.2 退货与退款闭环

当前：销售/采购来源单据退货、客户/供应商退款接口和回退能力已有基础实现，但 Web 新销售退货入口仍处于谨慎开放状态，已付款采购退货不会自动完成供应商退款。

缺口：

- 销售退货入口恢复前的真实业务验收。
- 多笔收付款、多张发票和部分退货组合回归。
- 采购退货后的供应商退款或应付冲减闭环。
- 退款失败重试、幂等、状态聚合和审计。
- 多订单、跨批次、现场自由退货的业务边界。

验收标准：退货、库存冲回、红字发票、客户/供应商退款和原单状态在失败重试后仍保持一致。

### 2.3 真实浏览器与实体设备验收

必须覆盖：

- 销售、采购、库存、用户、安全、打印和报表主路径。
- 不同角色、不同公司和不同数据权限。
- 浏览器刷新、JWT 刷新、2FA、全设备注销和异常提示。
- A4/半 A4 打印分页、字体、签章栏、ZIP 和合并 PDF。
- 移动端实体 Android 设备、扫码、相机、文件下载和版本升级。

### 2.4 Staging 与运维演练

缺口：

- 按 runbook 初始化并验收真实 staging 站点。
- 数据库与文件备份、恢复、回滚和维护模式演练。
- 生产同域反向代理、HTTPS、缓存和跨域策略验证。
- 后台队列、scheduler、错误日志、容量和健康检查告警。
- 发布迁移清单和失败回退责任人。

## 3. P1：企业经营风险控制

### 3.1 客户信用控制

缺口：

- 公司维度信用额度和信用期限。
- 逾期应收、超额赊销和下单前统一校验。
- 禁止、警告、审批放行和临时额度。
- 销售订单、发货、开票三个节点的一致控制口径。

### 3.2 批次与保质期

缺口：

- 商品批次策略、生产日期、有效期和临期阈值。
- 收货批次录入、批次库存和批次追溯。
- FEFO/FIFO 出库建议和强制策略。
- 临期、过期、批次召回和报损。
- 打印和扫码中的批次字段贯通。

### 3.3 客户和供应商深度治理

缺口：

- 多联系人、多地址独立维护和主记录切换。
- 客户公司维度信用额度子表。
- 销售/采购历史聚合和应收/应付钻取。
- 标签、区域、业务员/采购员归属、等级和审计记录。
- 合并、去重和引用保护。

### 3.4 仓库与库位治理

缺口：

- 库区、库位、容量、负责人和默认成本中心。
- 仓库级用户权限和移动作业范围。
- 禁用、迁移、清空和引用保护。
- 仓库资料质量与审计。

### 3.5 报表与资金分析

缺口：

- 发票级、付款级和库存凭证级钻取。
- CSV/Excel 导出和大数据量异步导出。
- 多公司真实对账、跨月/季度回归和性能基线。
- 指标口径版本和报表快照。

### 3.6 条码与移动仓储作业

缺口：

- 外部商品信息 provider 和多源降级策略。
- 连续扫码、批量扫码和重复扫码处理。
- 收货、拣货、复核、盘点和调拨扫码闭环。
- 批次/效期条码与异常商品治理。

### 3.7 AI Copilot 平台化与单据草稿

当前本地可实施的 AI 主链路已经基本完成：只读工具、三类核心业务草稿、模型策略/预算/灰度/降级、Prompt 与 Embedding 发布治理、商品数据任务、OTLP trace/score、固定评测、共享异步连接池、分布式限流/预算/熔断、独立向量队列、专项压测、Qdrant snapshot，以及 Langfuse PostgreSQL/ClickHouse/MinIO 联合备份恢复均有实现和验证证据。

剩余范围：

- 把 Orchestrator 直接等待 Langfuse OTLP 写入升级为批处理/有界队列或 OpenTelemetry Collector，避免观测端慢响应增加 AI 请求尾延迟，并补充丢弃、重试、积压和写入失败指标。
- 完成正式生产 Secret Manager、Langfuse Project Key/恢复根密钥轮换、SSO/RBAC、成本看板、告警负责人和保留策略；本地 env、初始化账号或单机健康不能替代这些外部部署项。
- 将单节点 Compose 基线升级为生产多副本/负载均衡与托管 PostgreSQL、ClickHouse、Redis、对象存储或等价 HA 方案，并在真实 staging 完成故障摘除、容量和恢复验收。
- 修复外部 `erp-embedding` v2 Provider 的 `float + str` 故障后，构建、评测和受控发布新 collection；在线 v1 alias 在此之前保持不变。
- 扩大人工标注的中文检索质量集，清理历史 HTTP 测试商品噪声，并建立生产数据质量与检索回归门禁。

验收标准：AI 不创建正式单据，不泄露越权数据；回答和草稿均可追溯；模型或 Prompt 升级通过固定评测；成本、失败和用户反馈可观测。

## 4. P2：高级企业治理与工程收尾

### 4.1 用户与权限高级治理

核心用户模块已完成，剩余增强：

- 角色申请、审批、临时授权和自动到期。
- 定期权限复核和离职/转岗回收。
- 组织架构、岗位、员工档案和代理授权。
- 可信设备、异常登录告警和安全事件报表。
- 完整权限模拟器：合并菜单、DocPerm、User Permission 和指定记录判断。
- OAuth/LDAP/SSO 的正式配置与验收。

### 4.2 Web 工程清理

- 删除已隐藏但不再需要的模板页面、模板 service 和 mock 依赖。
- 移除未接入的手机号登录及第三方登录视觉占位，或正式实现对应认证。
- 收紧 `access.ts` 中按常见 ERPNext 角色宽松匹配的规则。
- 解决 Jest 既有 open handle，并建立浏览器 E2E 测试。
- 验证生产构建、chunk 缓存和前端错误监控。

### 4.3 导入导出治理

当前 CSV 导入适用于小批量维护。企业级大批量场景仍需：

- 后台异步导入任务和导入批次。
- 预校验、错误明细下载、失败重试和回滚。
- 导入模板版本、权限、审批和审计。

### 4.4 打印运营增强

核心打印功能已经完成，剩余主要是运营和生产验收：

- 纸张、页边距、水印和角色策略的可运营设置。
- 真实对象存储 provider 验证。
- 真实打印机和不同浏览器的样张回归。
- 标签打印、热敏打印和厂商协议属于独立扩展，不纳入当前核心 A4 打印完成度。

## 5. 推荐实施顺序

1. 库存盘点生命周期。
2. 销售/采购退货退款闭环。
3. Staging、浏览器、实体设备和打印验收。
4. 客户信用控制。
5. 批次与保质期。
6. 客户/供应商及仓库深度治理。
7. 报表钻取、导出和性能。
8. AI 生产异步观测、HA/Secret/SSO/告警、真实 staging 与 v2 Embedding Provider 收口。
9. 条码仓储作业和高级用户治理。
10. 模板清理、E2E、前端错误监控和大批量导入。
